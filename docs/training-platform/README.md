# Leaps Up — Training Platform

A guided, roadmap-based training system to teach both **technical** and **non-technical**
people how to build projects using Claude.

## Goal

- Learners follow a **roadmap** and can see where they are and what's next.
- Sections are learned **sequentially** — you cannot jump ahead.
- Each section ends in a **quiz/assessment** that gates the next section.
- A **coach** reviews and approves the roadmap and content before learners see it.
- A **manager** sees an overall **dashboard** of everyone's progress.
- **Content is generated by Claude** and approved by the coach.
- It should be **simple to manage** — no heavy app to run and maintain.

## The four roles

| Role | Does what | Touches |
|------|-----------|---------|
| **Trainee** | Learns sections in order, takes quizzes | The training site |
| **Coach** | Reviews & approves Claude-generated content and roadmaps | Content files / review page |
| **Manager** | Watches overall progress | Dashboard |
| **Claude** | Generates roadmap + lesson content + quizzes | This repo |

## The three layers (both approaches share this shape)

Regardless of implementation, the system separates into three concerns. Keeping them
separate is what keeps it manageable.

1. **Authoring** — Claude drafts content → coach approves → it becomes visible.
2. **Delivery** — what the trainee sees: roadmap, sequential sections, quizzes.
3. **Progress & dashboard** — the shared record of who did what, and the manager view.

Only layer 3 needs a shared data store. That single decision is what separates the
two approaches below.

## Two approaches

| | **Approach A — Static + Google Sheets** | **Approach B — Supabase** |
|---|---|---|
| Best when | Simple internal training, small teams, fast start | Real accounts, secure gating, formal certification |
| Frontend | Static HTML/JS on GitHub Pages | Static HTML/JS (or app) on any host |
| Data store | Google Sheet (via Apps Script endpoint) | Supabase Postgres database |
| Auth / identity | Honor-system (name/email entered once) | Real login (email/OAuth) |
| Sequential gating | Soft (client-side) | Hard (server-enforced via RLS) |
| Content approval | `approved` flag in files / git review | `approved` flag in DB, coach role |
| Cost | Free | Free tier, paid as you scale |
| Setup effort | Low (~1 day) | Medium (2–4 days) |
| Maintenance | Very low | Low–medium |

- **[Approach A — Static + Google Sheets](./approach-a-static-sheets.md)** ← recommended starting point
- **[Approach B — Supabase](./approach-b-supabase.md)** ← upgrade path when you need real auth

## Recommendation

Start with **Approach A**. It satisfies every requirement (roadmap, sequential learning,
quizzes, coach approval, manager dashboard, Claude-generated content) with essentially no
infrastructure. Move to **Approach B** only when you need enforced access control, verified
identities, or auditable certification — the content files and quiz format carry over
unchanged, so migrating later is cheap.
